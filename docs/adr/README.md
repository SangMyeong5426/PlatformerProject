# Architecture Decision Records

되돌리기 어렵거나 저장소 전체에 영향을 주는 결정을 Architecture Decision Record(ADR)로 남긴다.

## 무엇을 쓰는가

| | 예 |
| --- | --- |
| **쓴다** | 코드 배치 구조, 공통 골격의 설계 방식, 마이그레이션 수행 방법, 저장소 운영 규칙 |
| **쓰지 않는다** | 결함 수정, 문서 편집, 이미 정한 방식을 그대로 적용하는 작업, 값 하나 변경 |

판단이 애매하면 **"나중에 이걸 왜 이렇게 했는지 설명해야 하는가"**를 기준으로 한다. 설명이
필요하면 ADR 이다.

## 쓰는 방법

1. `template.md` 를 복사해 `NNNN-short-title.md` 로 만든다. 번호는 `0001` 부터 순서대로.
2. **구현 전에** 쓴다. 하고 나서 쓰면 이미 정해 놓고 근거를 맞추게 된다.
3. 실제로 선택 가능한 후보를 비교하고, **고르지 않은 이유**와 **다시 볼 조건**을 남긴다.
   후보가 둘에 못 미치면 그 사실과 이유를 적는다.
4. 이전 결정을 바꿀 때는 기존 문서를 지우지 않고 새 ADR 에서 대체 관계를 기록한다.
5. ADR 을 새로 썼거나 적용했으면 해당 work log 에 어느 ADR 인지 적는다.

**소급 작성한 ADR 은 그 사실을 밝힌다.** 이미 구현한 뒤에 쓴 것과 구현 전에 쓴 것은 신뢰도가
다르다. 소급인 것을 숨기면 나머지 ADR 도 믿을 수 없게 된다.

**번호가 비는 것은 정상이다.** 쓰다 만 ADR 을 지우면 그렇게 되고, 그 자리를 다시 쓰면 이력이
헷갈린다.
