# ADR 0003: 스테이지 분기를 `StageId` enum 과 배열 인덱스로 일원화한다

- 상태: Accepted
- 날짜: 2026-08-31
- 소급 작성: **예.** 실제 적용은 2026-08-30 (`93a4303d`, `471affb4`, `4391e103`)

## 배경

"몇 번째 스테이지인가"가 **서로 다른 방식으로 세 군데에 하드코딩**돼 있었다.

| 어디 | 어떻게 |
| --- | --- |
| `BoolManager` | `static bool` 4개 (`FirstStageBossDie` …) |
| `EnemyCountManager` | 필드 4개 + `static bool` 4개 + 씬 이름 4중 분기 |
| 보스 포탈 | 클래스 4개. 각자 자기 플래그를 읽는다 |
| `EnemyCountText` | 스테이지 4 x 언어 2 = 8중 분기 |

같은 개념인데 **표현이 전부 달라서** 스테이지를 하나 추가하면 네 군데를 찾아 고쳐야 했고,
"3스테이지"를 뜻하는 값이 코드마다 다른 이름으로 존재했다.

## 검토한 선택지

**A. `enum` + 배열 인덱스**

```csharp
public enum StageId { First = 0, Second = 1, Third = 2, Fourth = 3 }
```

- 장점: **인스펙터에 드롭다운으로 뜬다.** 포탈 컴포넌트를 하나로 합칠 때 이게 결정적이었다
- 장점: 배열 인덱스로 바로 쓸 수 있어 4중 분기가 배열 조회 한 줄이 된다
- 단점: enum 순서와 배열 인덱스가 묶여 있다. 순서를 바꾸면 저장된 값이 어긋난다

**B. `ScriptableObject` 로 스테이지를 자산화한다**

- 장점: 스테이지마다 씬 이름·표시명·클리어 조건을 함께 담을 수 있다
- 단점: **자산 4개를 만들고 참조를 씬마다 연결해야 한다.** 지금 필요한 것은 "구분자" 뿐인데
  비용이 크다
- 단점: `static` 플래그를 자산으로 옮기면 **플레이 모드에서 값이 남는 문제**가 생긴다.
  지금은 `BoolReset` 이 초기화하는 구조인데 그 흐름을 다시 설계해야 한다

**C. 문자열 씬 이름을 그대로 키로 쓴다**

- 장점: 새 스테이지를 코드 변경 없이 추가할 수 있다
- 단점: **오타가 컴파일에 걸리지 않는다.** 지금도 씬 이름 비교가 흩어져 있어 생긴 문제다
- 단점: 인스펙터에서 자유 입력이 되어 잘못된 값이 들어갈 수 있다

## 결정

**A — `enum` + 배열 인덱스.**

결정적인 이유는 **인스펙터 드롭다운**이다. 이 작업의 목표 중 하나가 포탈 클래스 4개를 하나로
합치는 것이었는데, 합치려면 "어느 스테이지인가"를 **인스펙터에서 지정**할 수 있어야 했다.
enum 은 Unity 가 드롭다운으로 그려 주고 잘못된 값이 들어갈 수 없다.

C를 고르지 않은 이유가 그 반대다. 문자열은 인스펙터에서 자유 입력이 되고 오타가 런타임까지
간다. **지금 고치려는 문제가 정확히 그것**이었다.

B는 담을 것이 생기면 그때 간다. 지금 필요한 것은 구분자 하나다.

**값을 명시적으로 적었다** (`First = 0`). `BoolManager` 가 배열 인덱스로 쓰기 때문이다.
enum 순서를 바꾸면 조용히 어긋나므로 선언부에 주석으로 남겼다.

## 영향

**실제로 얻은 것**

만들 때는 보스 사망 처리에만 쓸 생각이었는데 **세 군데에서 재사용됐다.** 처음 만든 목적보다
넓게 쓰인 것이 이 결정의 가장 큰 성과다.

- `BoolManager`: `static bool` 4개 → `bool[]` + API 3개
- `EnemyCountManager`: 4중 분기 → 배열 조회. `TryGetStage()` 로 씬 이름 매핑을 공유
- `BossClearPortal`: 클래스 4개 → 1개 (68줄 → 21줄)
- `EnemyCountText`: 8중 분기 → 언어 2중 분기 (55줄 → 35줄)

**비용 · 위험**

- **enum 순서가 배열 인덱스와 묶여 있다.** 순서를 바꾸거나 중간에 값을 끼워 넣으면 저장된
  플래그가 어긋난다. 컴파일에 걸리지 않는다
- 스테이지를 추가하면 `enum` 과 배열 크기 두 곳을 함께 고쳐야 한다. `bossCleared` 배열이
  `new bool[4]` 로 하드코딩돼 있다

## 다시 볼 조건

- **스테이지마다 딸린 데이터가 생기면** (표시명, 해금 조건, 배경 음악 등) B 로 간다.
  지금은 구분자만 필요하다
- **스테이지를 실제로 추가하게 되면** 배열 크기 하드코딩을 함께 정리한다
