# ADR 0004: 스크립트를 `Assets/Scripts/` 아래 도메인별로 모은다

- 상태: Accepted
- 날짜: 2026-08-31
- 소급 작성: 아니오

## 배경

사용자가 작성한 스크립트 **143개가 디렉터리 30개**에 흩어져 있다. 문제는 개수가 아니라
**배치가 내용과 무관하다**는 것이다.

| 지금 | 무엇이 문제인가 |
| --- | --- |
| `Assets/4. UI/2. Scripts/` 에 69개 | **폴더 이름은 UI 인데 보스 로직·아이템·대화가 전부 여기 있다** |
| `Assets/2. Player/02. Scripts/Boss/` 에 7개 | **대지·얼음 보스가 플레이어 폴더 안에 있다** |
| `Assets/1. Monster/3.Prefabs/Boss/` 에 5개 | 프리팹(에셋) 폴더 안에 코드가 섞여 있다 |
| `Assets/4. UI/Sound/` 에 3개 | 같음 |
| `Assets/` 바로 아래 3개 | `Buttonclick`, `End`, `TouchObj` |
| `X/`, `test/` 폴더에 16개 | 이름만으로는 살았는지 죽었는지 알 수 없다 |

가장 두드러지는 것은 **보스 코드가 두 곳으로 쪼개져 있다**는 점이다. 2단계에서 보스 4종을
`Basic_Boss` 공통 골격으로 묶었는데(ADR-0002), 정작 파일은 불·바람이
`Assets/4. UI/2. Scripts/Boss/` 에, **대지·얼음이 `Assets/2. Player/02. Scripts/Boss/` 에**
있다. 같은 부모를 상속하는 네 클래스를 보려면 두 트리를 오가야 한다.

`1. Monster`, `2. Player`, `4. UI` 같은 번호 접두 폴더는 **에셋(스프라이트·프리팹·씬)을 담는
구획**이다. 코드가 그 안에 들어가면서 "이 스크립트가 어느 에셋 폴더에서 만들어졌는가"가
배치 기준이 됐고, 그건 **읽는 사람에게 아무 정보도 주지 않는다.**

## 검토한 선택지

**A. 그대로 둔다**

- 장점: 위험이 0이다. Unity 에서 파일을 옮기는 것은 씬 참조를 깨뜨릴 수 있다
- 단점: **이 저장소의 목적은 포트폴리오다.** 코드를 읽으러 온 사람이 보스 4종을 한 화면에서
  볼 수 없다는 것은 정리가 안 됐다는 뜻이다
- 단점: 앞으로의 리팩토링(C단계 Talk 통합)도 파일을 찾는 것부터 시작해야 한다

**B. `Assets/Scripts/` 를 만들고 도메인별로 모은다**

- 장점: **"무엇에 관한 코드인가"가 배치 기준이 된다.** 보스 4종이 한 폴더에 모인다
- 장점: Unity 는 스크립트를 경로가 아니라 `.meta` 의 GUID 로 참조하므로 **`.cs` 와 `.meta` 를
  함께 옮기면 씬 참조가 유지된다.** 코드는 한 줄도 바뀌지 않는다
- 단점: 143개를 옮기면 `git log --follow` 없이는 이력 추적이 번거로워진다
- 단점: 옮기는 도중 `.meta` 를 빠뜨리면 **해당 스크립트를 쓰는 모든 씬 컴포넌트가
  `Missing` 이 된다**

**C. B + Assembly Definition(`asmdef`) 으로 어셈블리를 쪼갠다**

- 장점: 컴파일 시간이 줄고 의존 방향을 컴파일러가 강제한다
- 단점: **지금 의존 관계가 정리돼 있지 않다.** `Basic_Boss` 가 `BoolManager` 를 부르고
  `Gemstone` 이 `BoolManager` 를 읽는 식으로 얽혀 있어, 어셈블리를 나누면 순환 참조가 난다
- 단점: 배치를 먼저 정리해야 의존 관계가 보인다. **순서가 반대다**

**D. 폴더 이름의 번호 접두(`1.`, `2.`)를 유지한다**

- 단점: 그 번호는 2023년에 에셋을 정리하려고 붙인 것이고 코드와 관계가 없다. 유지하면
  같은 문제가 남는다

## 결정

**B — `Assets/Scripts/` 아래 도메인별.** `asmdef` 는 넣지 않는다.

```
Assets/Scripts/
├── Boss/          Basic_Boss, Boss_HpBar
│   ├── Fire/  Ice/  Earth/  Wind/    보스별 패턴과 투사체
│   └── Mode/                          보스 러시 모드
├── Monster/       일반 몬스터
├── Player/        이동·공격·무기별 (Sword / Spear / Shield)
├── Item/          인벤토리·드롭·보석
├── Talk/          대화 시스템
├── Portal/        스테이지 이동
├── Scene/         씬 전환·게임 매니저
├── Select/        캐릭터 선택
├── Sound/         BGM·SFX
├── UI/            HUD·텍스트
├── Level/         카메라·배경·플랫폼
├── Core/          BoolManager, BoolReset, StageId, EnemyCountManager 등 전역 상태
└── Legacy/        옛 구현. 아직 씬이 참조하지만 현재 설계에 속하지 않는다
```

**`Legacy/` 를 따로 두는 이유.** `X/`, `test/` 폴더의 16개 중 **9개는 아직 씬·프리팹이
참조하고 있다.** 이름이 `X` 라고 해서 죽은 코드가 아니다. 지우면 씬이 깨진다.

그렇다고 도메인 폴더에 섞으면 **현재 설계인 것과 남아 있을 뿐인 것이 구분되지 않는다.**
`Legacy/` 는 "아직 지울 수 없지만 새로 참조하지 말 것"을 이름으로 말한다.

**참조가 0건인 7개는 옮기지 않고 삭제한다.** 이동 커밋과 삭제 커밋을 분리한다.

`asmdef` 를 넣지 않는 이유는 **순서** 다. 의존 관계가 얽혀 있어 지금 어셈블리를 나누면
순환 참조가 난다. 배치가 정리되면 의존 방향이 보이고, 그때가 `asmdef` 를 넣을 시점이다.

## 어떻게 옮기는가

**`git mv` 로 `.cs` 와 `.meta` 를 함께 옮긴다.** Unity 는 `.meta` 안의 GUID 로 스크립트를
참조하므로 둘이 같이 움직이면 씬·프리팹은 아무것도 모른다. **코드는 한 줄도 바뀌지 않는다.**

**Unity 에디터를 닫고 옮긴다.** 에디터가 켜져 있으면 `.cs` 는 도착했는데 `.meta` 가 아직인
순간을 `AssetDatabase` 가 볼 수 있고, 그러면 Unity 가 **새 GUID 를 발급해 버린다.** 그
스크립트를 쓰는 모든 컴포넌트가 `Missing` 이 된다. 되돌리기 어려운 사고다.

**단계로 쪼개서 옮긴다.** 143개를 한 커밋에 넣지 않는다.

| 단계 | 범위 | 왜 이 순서인가 |
| --- | --- | --- |
| a | 보스 | 값이 가장 크다. 두 트리로 갈라진 것이 한 폴더로 모인다 |
| b | `Core/` 와 `Assets/` 루트 직속 | 개수가 적고 참조가 명확하다 |
| c | 나머지 도메인 | |
| d | 죽은 코드 7개 삭제 | 이동과 섞지 않는다 |

**각 단계마다 GUID 보존을 확인한다.** 옮긴 파일의 `.meta` GUID 가 이동 전후로 같은지,
그리고 씬·프리팹의 `Missing` 참조가 0건인지 본다.

## 영향

**쉬워지는 것**

- 보스 4종이 한 폴더에 모인다. ADR-0002 의 공통 골격이 파일 배치로도 드러난다
- 남은 리팩토링(C단계 Talk 통합)에서 대상 파일을 찾는 비용이 없어진다
- `Legacy/` 가 "손대지 말 것"을 이름으로 표시한다

**비용 · 위험**

- **`git log` 가 이동 지점에서 끊긴다.** `--follow` 를 써야 한다. 이 문서가 그 지점을
  기록한다
- **`.meta` 를 빠뜨리면 씬이 깨진다.** 단계마다 GUID 대조로 막는다
- 옮기는 동안 Unity 를 닫아야 한다
- 번호 접두 폴더(`1. Monster` 등)에는 에셋만 남는다. **의도한 결과다** — 그 폴더의 원래
  역할이다

## 다시 볼 조건

- **의존 관계가 정리되면** `asmdef` 도입을 다시 본다. 지금은 순환 참조 때문에 불가능하다
- **`Legacy/` 가 비면** 폴더를 없앤다. 씬이 참조를 끊는 만큼 줄어든다
