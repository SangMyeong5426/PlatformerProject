# README 에 쓰는 그림

이 폴더의 파일은 전부 [`README.md`](../../README.md) 가 참조한다. **찍는 기준을 먼저 적어
두는 이유**는, 나중에 다시 찍거나 스테이지를 고친 뒤 갱신할 때 같은 장면이 나와야 하기
때문이다.

현재 README 에는 세 자리가 주석으로 비어 있다. 아래 순서대로 채운다.

## ① `gameplay.gif` — README 맨 위

**가장 중요한 한 장이다.** 처음 오는 사람이 보는 첫 화면이고, 이 저장소에서 "게임이 실제로
돌아간다"를 증명하는 유일한 수단이다.

| | |
| --- | --- |
| 장면 | 보스전. `1_StageBoss`(대지) 또는 `4_StageBoss`(바람) |
| 길이 | 5~8초. 공격 → 피격 → 보스 패턴 한 번이 보이게 |
| 크기 | 가로 720px 이하, **3MB 이하**. GitHub 은 10MB 넘는 이미지를 표시하지 않는다 |
| 담을 것 | 보스 체력바 · 플레이어 HUD · 패턴 하나 |
| 담지 말 것 | Unity 에디터 UI. 게임 화면만 |

바람 보스가 텔레포트와 탄막이 있어 화면이 가장 많이 움직인다.

## ② 스크린샷 4장 — `게임 보기` 절

| 파일 | 씬 | 무엇이 보여야 하나 |
| --- | --- | --- |
| `select.png` | `UI_Select` | 검·창·방패 세 캐릭터와 난이도 선택 |
| `stage.png` | `2_Stage` 또는 `3_Stage` | 플랫포머 지형 · 몬스터 · 인벤토리 HUD |
| `boss.png` | 아무 보스 씬 | 보스 · 체력바 · 이펙트 |
| `talk.png` | `Tutorial` 또는 NPC 앞 | 대화창과 대사 |

전부 같은 해상도로 찍는다. 표에 나란히 놓이므로 크기가 다르면 줄이 어긋난다.

`select.png` 와 `talk.png` 는 **2023년에 내가 만든 화면**이라 [`README` 의 역할
절](../../README.md#2023년-팀-프로젝트에서-제가-한-것)과 이어진다.

## ③ `playmode-test.gif` — `검증을 어떻게 했는가` 절

**게임 화면이 아니라 터미널 녹화다.** 이 저장소의 주장 전체가 "CI 없이 검증 수단을 직접
만들었다"인데, 지금 그 근거가 텍스트로만 있다. 도구가 실제로 도는 장면 하나가 그 문단을
전부 뒷받침한다.

```bash
brew install vhs
vhs docs/media/playmode-test.tape
```

`vhs` 를 쓰는 이유는 **녹화를 파일로 정의해 커밋할 수 있기 때문이다.** `.tape` 를 함께
두면 나중에 같은 GIF 를 다시 만들 수 있고, 어떻게 만든 그림인지가 저장소에 남는다.
asciinema 는 재생에 플레이어가 필요해서 README 임베드에 불리하다.

담을 것은 `scripts/playmode-test --last` 가 **10개 PASS** 를 출력하는 장면이다.

## 규칙

- **에디터 화면을 그대로 찍지 않는다.** 게임 뷰만 나오게 한다.
- **코드는 그림으로 찍지 않는다.** 마크다운 코드 블록과 mermaid 로 넣는다 — 복사되고,
  검색에 걸리고, 다크/라이트 모드에서 둘 다 읽힌다.
- 파일 이름은 위 표대로 쓴다. README 주석이 그 이름을 가리키고 있다.
