# Portfolio Records

work log 와 ADR 에 쌓인 기록을 **면접에서 설명할 수 있는 형태**로 정리한다.

이 저장소의 최종 산출물이다. 리팩토링 자체가 아니라 이 문서들이 지원 서류에 들어간다.

## 작성 조건

- 의미 있는 구현, 기술 결정, 결함 해결 또는 검증 방법이 있어야 한다.
- **근거를 연결한다.** 관련 work log, ADR, 커밋 해시를 가리킨다.
- 수치는 **측정 근거가 있을 때만** 쓴다. 측정하지 않았으면 `측정하지 않음`이라고 적는다.
  "성능이 개선되었다"처럼 재지 않은 것을 성과로 적지 않는다.
- **실패와 한계도 남긴다.** 되돌린 접근과 검증하지 못한 항목은 감점 요소가 아니라
  판단 근거를 보여주는 자리다.

조건을 만족하는 작업이 쌓인 뒤 [`template.md`](template.md) 를 쓴다.

## 이 프로젝트에서 특히 설명할 만한 것

포트폴리오로 정리할 때 후보가 되는 축들이다. 작업이 끝나면 여기서 골라 쓴다.

- 동작을 바꾸지 않는 리팩토링을 **어떻게 검증했는가** — 테스트가 하나도 없는 저장소에서
- 2023년 팀 코드를 **원 작성자에게 물을 수 없는 상태**로 정리한 방법
- Unity 에서 씬 참조를 깨지 않고 구조를 바꾸는 방법
