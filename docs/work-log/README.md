# Work Log

하루치 작업에서 **무엇을 했고 무엇이 어긋났는지** 남긴다.

## 왜 이 폴더가 있는가

본보기로 삼은 [`skalounge`](https://github.com/simonjiho/skalounge) 는 Squash merge 만 쓰므로
**PR 본문이 곧 `main` 에 남는 유일한 기록**이고, 되돌린 접근·발견한 결함·검증하지 못한 항목을
전부 거기 적는다.

이 저장소는 1인 작업이라 **PR 을 쓰지 않기로 했다.** 그래서 그 기록의 자리가 없어졌다.
커밋 메시지는 대신하지 못한다 — 커밋은 "이 변경"만 설명하고, **"해봤다가 되돌렸다"는 어느
커밋에도 속하지 않아 적을 자리가 없기 때문이다.** 이 폴더가 그 자리다.

## 파일명

`YYYY-MM-DD-short-title.md`. 하루에 성격이 다른 작업을 여러 건 했으면 나눠 쓴다.

## 반드시 남길 것

- **시도했다가 되돌린 접근과 되돌린 이유**
- **작업 중 발견해서 고친 결함** — 무엇이 잘못됐고, 어떻게 드러났고, 왜 그렇게 됐는지
- **검증하지 못한 항목과 그 이유**
- **오판했다가 정정한 내용** — 정정했다고 지우지 않는다

성공한 결과만 나열한 기록은 왜 그 결과에 도달했는지 설명하지 못한다.

## 쓰지 않아도 되는 것

- 커밋 메시지가 이미 말하는 변경 내용의 반복. 커밋 해시를 가리키면 된다
- 파일 목록. `git show` 가 더 정확하다
