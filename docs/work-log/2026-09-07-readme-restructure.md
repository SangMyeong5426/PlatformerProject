## 왜 구성을 바꿨나 — 독자가 둘이다

초안은 첫 문단부터 "동작을 바꾸지 않는 리팩토링을 어떻게 검증했는가"로 들어간다. 이 저장소가
자랑할 것이 그것이라 맞는 판단이지만, **읽는 사람이 한 종류가 아니다.**

| 독자 | 시간 | 알고 싶은 것 |
| --- | --- | --- |
| 인사담당자 | 30초 | 이게 뭔가. 이 사람이 뭘 했나 |
| 개발 리뷰어 | 5분~ | 어떻게 판단했나. 그 판단을 어떻게 검증했나 |

초안은 두 번째 독자만 상정하고 있었다. **정리 대상이 무엇인지 모르는 채로 검증 방법론부터
읽게 된다.** 그래서 위에서 아래로 깊이가 깊어지는 순서로 바꿨다 — 위쪽 절반은 게임과 역할,
아래쪽 절반은 기존 내용 그대로.

기존의 `검증을 어떻게 했는가` 절은 **한 글자도 고치지 않았다.** 문제는 그 절의 내용이 아니라
그 절에 도달하기 전에 아무 맥락이 없다는 것이었다.

## 그림을 어떻게 쓸지 정했다

"리팩토링 절에 게임 화면을 막 넣기보다 코드를 보여주는 게 낫지 않나"에서 시작해, 절마다
**무엇을 증명하려는지에 따라 매체를 나눴다.**

| 증명하려는 것 | 매체 |
| --- | --- |
| 이런 게임이 실제로 돈다 | 플레이 GIF · 스크린샷 |
| 구조가 이렇게 바뀌었다 | mermaid 다이어그램 |
| 이 한 줄이 왜 결함이었나 | ` ```diff ` 블록 |
| 검증 도구가 실제로 돈다 | 터미널 녹화 GIF |

**코드는 이미지로 찍지 않기로 했다.** IDE 캡처는 복사가 안 되고, 검색에 안 걸리고,
다크/라이트 한쪽에서 깨지고, 무엇보다 **읽는 사람이 확인할 수 없는 주장**이 된다. 이
저장소의 무기가 "검증 가능함"이라 특히 손해다. 마크다운 코드 블록과 mermaid 로 넣는다.

촬영 기준은 [`docs/media/README.md`](../media/README.md) 에 따로 뒀다. 나중에 다시 찍거나
스테이지를 고친 뒤 갱신할 때 같은 장면이 나와야 한다.

**깨진 이미지 링크 대신 HTML 주석으로 자리를 잡아 뒀다.** 비어 있는 동안에도 문서가 멀쩡히
읽혀야 한다. 그림 없는 README 보다 깨진 이미지 아이콘이 붙은 README 가 나쁘다.

## 역할을 쓰는 방법 — 자기 신고를 검증 가능한 형태로

초안 TODO 중 하나가 "2023년 팀에서 내가 맡았던 역할"이었다. 포트폴리오에서 가장 믿기
어려운 종류의 문장이다. 팀 프로젝트에서 각자 자기 지분을 크게 말하기 때문이다.

그래서 **`git log` 로 확인할 수 있는 범위만 적고, 확인하는 명령을 README 에 같이 넣었다.**
근거는 둘이다.

- 파일을 처음 만든 커밋 (`--diff-filter=A`)
- 그 파일의 커밋 분포

이 기준으로 나온 것이 인벤토리 5개 · 대화 3개 · 게임 흐름 4개 · 전역 상태 2개 · 선택
화면 2개 · 보스 2종이다. 파일을 만졌다는 것과 만들었다는 것은 다르므로 **만든 것만** 적었다.

같은 절에 "나머지는 팀원들이 맡았고 2026년 리팩토링은 내 것이 아닌 부분까지 포함한다"를
붙였다. 남의 작업을 가져오지 않는다는 것을 먼저 밝히는 편이 낫다.

## 숫자를 다시 셌다

초안의 `한눈에` 표를 게임 / 리팩토링 둘로 나누면서 전부 다시 셌다.

| | |
| --- | --- |
| 팀 커밋 | 651 (`Main_Backup`) |
| 팀 기간 | 2022-10-06 ~ 2023-08-13 |
| 스테이지 씬 | 9 |
| 보스 4종 줄수 | 557 → 367 |
| 공통 골격 | 124 → 213 |

보스 줄수는 이관 직전 커밋(`2f023e52`)과 현재를 직접 비교해 얻었다. **이름이 바뀌어서
`One_Stage_Boss` · `Stage_2_monster` 로 찾아야 했다.**

`한눈에` 에서 `커밋 65개` 를 표 위쪽에서 내렸다. **커밋 수는 읽는 사람에게 아무것도
말해주지 않는다.** 대신 `테스트 0개 → 10개` 와 `결함 5건` 을 올렸다.

그리고 그 자리에 숫자를 적었다가 **바로 틀렸다.** `67개` 라고 쓴 뒤 커밋을 두 번 해서
68개가 됐다. 커밋 수를 README 에 숫자로 박으면 **커밋할 때마다 틀린다.** GitHub 비교
링크(`Main_Backup...refactor/boss-pattern`)로 바꿨다 — 항상 맞고, 읽는 사람이 눌러서
확인할 수도 있다.
