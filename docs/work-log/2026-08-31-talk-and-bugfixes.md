## 무엇을 했는가

리팩토링의 마지막 두 단계다. 대화 매니저 3종을 공통 골격으로 묶고(C), 미뤄 뒀던 버그를
정리했다(D). 작업 중 **세 번째 버그를 새로 발견했고 그게 가장 심각했다.**

## 사용자 확인을 먼저 받은 것

D단계 두 건은 **원래 의도를 알아야 정할 수 있는 것**이라 손대기 전에 물었다. 코드만 봐서는
오타인지 의도인지 구분되지 않는다.

**대지 탄환** — `Earth_Bullet` 이 자기 데미지가 아니라 `IceWave_Damage` 를 읽고 있었다.
같은 대지 계열인 `EarthGrow` 는 자기 값을 제대로 읽어서, 이 하나만 다르다는 게 근거였다.
오타로 보고 고치기로 했다.

**바람 패턴** — 처음엔 "판단 보류"로 결정됐다. 그런데 사용자가 **"바람 보스는 토네이도와
탄환 패턴, 돌진, 텔레포트로 구성된 것으로 기억한다"**고 해서 다시 확인했고, 그 기억이
맞았다.

## 확인해 보니 근거가 분명했다 — 바람 보스 패턴

`Random.Range(0, 4)` 로 패턴 4개를 뽑도록 써놓고 `case 2` 와 `case 3` 이 둘 다
`SpawnTornado()` 를 부르고 있었다.

결정적인 근거 둘.

**`SpawnBullet` 이 완성된 패턴인데 선택될 수가 없었다.** 자기 애니메이션(`"Bullet"`), 자기
효과음, 탄환 60발을 다 갖췄는데 호출되는 곳이 `SpawnTornado` 끝의 연쇄 한 군데뿐이라
**항상 토네이도 뒤에만** 나왔다.

**보스 4종이 전부 "고유기 2 + 돌진 + 텔레포트" 구조인데 바람만 고유기가 1개였다.**

| 보스 | 고유기 |
| --- | --- |
| 불 | 브레스 / 메테오 |
| 대지 | 바위 / 성장 |
| 얼음 | 얼음탄 / 2차공격 |
| **바람** | **토네이도 / 토네이도(중복)** |

`case 2` 를 복사해 만들고 함수 이름을 바꾸지 않은 전형적인 형태다.

**혼자 판단하지 않기를 잘했다.** 2단계에서는 동작 보존을 위해 중복을 그대로 배열에 두 번
넣어 두고 [`followups`](../followups.md) 로 넘겼는데, 그때 임의로 "확률 2배가 의도겠지"
하고 넘어갔으면 못 고쳤을 것이다.

### 검증 도구가 여기서 값을 했다

고친 뒤 `scripts/boss-pattern-diff` 를 돌렸더니 **헝크 1개, 바람 패턴 `[3]` 블록만 바뀌고
나머지 보스 5종 패턴 20개는 기준표와 그대로**였다. 의도한 것 외에 번진 변경이 없다는 것을
기계적으로 확인했다.

확인한 뒤 기준표를 갱신하고 `scripts/README.md` 에 **의도된 동작 변경**으로 기록했다.
그러지 않으면 도구가 영원히 `FAIL` 을 내서 쓸모가 없어진다.

## 새로 발견한 것 — 영어로 플레이하면 게임이 멈춘다

C단계에서 세 매니저의 구조를 나란히 놓고 보다가 발견했다.

`BonginTalkManager.GenerateDataENG()` 가 `talkDataENG` 가 **아니라 `talkData` 에** 같은 키
1, 2 를 다시 넣고 있었다. `Dictionary.Add` 는 중복 키에서 `ArgumentException` 을 던진다.

```csharp
void GenerateData()      { talkData.Add(1, "B를 눌러 봉인을 하자!"); ... }
void GenerateDataENG()   { talkData.Add(1, "Press B to seal!");  ... }  // ← talkDataENG 여야 한다
```

**연쇄가 나쁘다.**

1. `Awake` 에서 `ArgumentException` — 씬이 로드될 때마다
2. `talkDataENG` 가 빈 채로 남는다
3. `BonginTri` 가 플레이어 진입 시 `Time.timeScale = 0` 으로 멈춘다
4. `ActTalk()` 이 `talkDataENG[DataNum]` 에서 `KeyNotFoundException`
5. `DataNum` 이 올라가지 않으니 `DataNum == 3` 조건인 `PannelOff()` 가 영영 안 돈다
6. **`timeScale` 이 0 인 채로 남는다 — 게임이 멈춘다**

`Maze_Stage` 는 빌드 설정에 포함된 씬이다. 한국어에서는 `talkData` 에 한국어 대사가 들어
있어 동작한다. **그래서 드러나지 않았다.**

통합 커밋에 섞으면 이 수정이 묻히므로 먼저 별도 `fix` 로 처리했다.

## 대화 매니저 통합

세 매니저가 **다루는 채널 수만 다르고 하는 일이 같았다.** 채널마다 스페이스 처리 · 종료
판정 · 초상화 교체 · 대사 진행 코루틴 · 패널 닫기를 통째로 복붙했고, 대사 진행에는 한영
분기까지 두 벌씩 있었다. 571줄 → 386줄.

### 씬을 한 줄도 건드리지 않았다

`TalkManagerBase` 로 올린 필드(`God`, `Sword`, `Spear`, `Shield`, `PL`, `CharCodecopy`)는
**이름과 타입을 그대로 뒀다.** Unity 는 이름으로 직렬화하므로 상속으로 올라간 필드에도
기존 값이 그대로 붙는다.

진행도(`DataNum`)는 `static` 으로 각 매니저에 남겼다. `TalkTrigger` 가 읽고 있어서 옮기면
그쪽도 함께 바꿔야 한다. 채널이 람다로 읽고 쓴다.

### 보존하려고 일부러 그대로 둔 것들

동작을 바꾸지 않는 리팩토링이라, 정리하고 싶은 것을 참았다.

- **`Update` 안 세 판정을 채널별로 묶지 않았다.** 기존이 "스페이스 전부 → 종료 전부 →
  초상화 전부" 순서인데, 채널별로 묶으면 한 채널의 진행도 변화가 다음 채널 판정보다 앞서게
  되어 프레임 내 순서가 달라진다. 그래서 종류별로 세 번 돈다
- **`TalkManager` 채널 3 의 초상화 규칙에는 `else` 가 없다.** 조건 밖에서는 초상화를 그대로
  둔다. `PortraitFor` 가 `null` 을 돌려주면 건드리지 않도록 해서 유지했다
- **`EndTalkManager` 채널 2 의 초상화 규칙은 다른 채널과 반대다** (2·4 에서 신). 그대로 뒀다

### 대사를 손으로 옮겨 적지 않았다

52줄의 한국어·영어 대사를 다시 타이핑하면 오타가 섞인다. **원본의 `GenerateData` /
`GenerateDataENG` 본문을 그대로 추출해 대상 딕셔너리 식별자만 치환**했다.

검증도 기계로 했다 — 옛 파일과 새 파일에서 `Add` 호출을 뽑아 **(대상 딕셔너리, 키, 문자열)**
3요소로 대조했다. 52줄 완전 일치.

### 하지 않은 것 — 대사를 Localization 으로

대사는 여전히 코드에 하드코딩돼 있다. 프로젝트가 이미 Unity Localization 을 쓰는데
대화만 따로 논다.

**이건 리팩토링이 아니라 데이터 이관이다.** 대사가 사는 자리가 코드에서 에셋으로 바뀌고
테이블 편집은 에디터에서 해야 한다. 공통 골격 정리와 같은 커밋에 넣으면 무엇이 구조
변경이고 무엇이 데이터 이동인지 구분되지 않는다. [`followups`](../followups.md) 9번으로
넘겼다.

## 컴파일을 확인할 방법을 만들었다

오늘 하루 종일 **컴파일 상태를 모른 채로 커밋했다.** 스크립트 134개를 옮기는 동안에는
Unity 를 닫아 둬야 했고, 그 뒤로도 열어서 재임포트를 기다릴 일이 계속 밀렸다.

Unity 설치 안에 Mono 컴파일러(`mcs`)가 들어 있는 것을 확인하고 `scripts/compile-check` 를
만들었다. **소스 134개 error 0** — 오늘의 이동·삭제·통합이 전부 반영된 상태다.

만들면서 두 번 헛짚었다.

- **경로의 공백.** 응답 파일에 따옴표 없이 넘겨 참조 85개가 전부 소스 파일로 해석됐다.
  `Program Files` 와 `Assets/4. UI` 양쪽에서 같은 문제다. 오늘만 세 번째다
- **`netstandard` 참조 누락.** Localization 이 netstandard 2.1 타입을 노출해서, 없으면
  `CS0012` 가 나고 mcs 가 내부 예외로 죽는다. 처음엔 내 코드 문제인 줄 알았는데
  오류 위치가 전부 Localization 을 쓰는 파일이라 참조 문제인 걸 알았다

**한계를 문서에 적었다.** Unity 는 Roslyn 을 쓰고 이쪽은 mcs 다. 정의 기호를 넣지 않아
`#if` 로 갈리는 코드는 다르게 컴파일된다. **실패는 확실한 신호이고, 통과는 "적어도 이
범위에서는 문제가 없다"는 뜻이다.**
